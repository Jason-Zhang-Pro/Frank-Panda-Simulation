# Gazebo 原始实验记录

每种算法的有效任务种子均为 1、2、3，预算为每个全局搜索 5 秒。`raw/` 保存启动/运行日志、任务 CSV、状态事件 CSV。`trials.csv` 为任务记录合并，`phases.csv` 从规划日志提取阶段耗时、长度与判定，`summary.csv` 对同类接近段及任务计数作汇总。

`plan_success` 表示成功生成并通过后处理检查的轨迹，不代表该段实际到位。`execution_arrived` 为空表示没有收到该段实际到位状态；不能填成成功。笛卡尔 IK 段不参与 OMPL 搜索长度平均，相关字段留空。首解与搜索时间具有日志精度限制。

长度为七轴角度空间长度，非末端距离。任务 CSV 的 `planned_length_rad` 和 `actual_sampled_length_rad` 对失败试验仅累计到终止时刻，不应比较为完整任务路径。物体最终坐标是终止消息附近最新实际采样，不是手工设置值。

原始输入、控制配置和环境信息保留在本目录；`source_sha256.txt` 记录实验实现文件指纹。输入哈希中的绝对路径是实验机原路径，可按文件名核对快照内容。环境信息在恢复采集时再次记录，时间不等同于第一项任务开始时间。

原有 GUI 仿真保持运行，测试实例与其隔离；早期顺序试验共用独立域 87，启动服务超时后未提交任务，后续试验改为每次使用独立域/分区。仅对基础设施故障重试，没有丢弃或重跑已提交的失败任务。`infrastructure_failures.txt`、启动重试日志和 `batch.log` 保留此过程。

这是小样本工程实验，支持定位当前配置的性能和失败环节，不构成对任一算法普遍优劣的证明。

部分 Gazebo 关闭日志包含退出阶段崩溃，发生于任务结果写入后；未隐去这些日志，也未作为任务运行中搜索失败统计。
