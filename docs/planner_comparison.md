# RRT、RRT-Connect、RRT*：同一 C++ 框架中的比较

## 实现差异

三个规划器均调用 OMPL 的 C++ 实现。统一使用七维 RealVectorStateSpace、URDF 关节限位、0.15 rad 范数的最大扩展步长、MoveIt/FCL 状态检查及相同场景。状态有效性分辨率按关节空间范围折算至约 0.02 rad；后处理另有更密复检。

| 算法 | 本项目调用 | 主要区别 | 对比关注点 |
|---|---|---|---|
| RRT | `ompl::geometric::RRT` | 从起点扩展单树，目标偏置 0.05 | 首解耗时、成功率、绕行长度 |
| RRT-Connect | `ompl::geometric::RRTConnect` | 两棵树交替扩展并尝试连接 | 获得可行解的效率，不保证最短 |
| RRT* | `ompl::geometric::RRTstar` | 选父节点、重连，优化关节空间路径长度 | 首解与最终解、预算内代价改进 |

RRT* 设置 PathLengthOptimizationObjective 和延迟碰撞检查，默认在预算内持续优化。RRT / RRT-Connect 通常有精确解就返回，不能只比较 solve 总时长便断言谁效率低。RRT* 的渐近性质不代表有限时间找到全局最优，更不代表轨迹时间最短或末端路径最短。

比较时统一碰撞模型、起终点、搜索预算和后处理配置，避免把实现配置差异当作算法性能差异。定量结论以重复实验数据为准。

## 三组后处理消融

每个算法都跑以下三组：

1. `raw`：关闭 shortcut 和 B 样条，保留原五次时间分配及复检。
2. `shortcut`：开启无碰撞远端直连，关闭 B 样条。
3. `bspline`：开启 shortcut 和 B 样条；失败可回退，CSV 明确记录类型。

shortcut 主要减少冗余路点和折线绕行，不保证曲线可导；B 样条改变几何形状并提供连续中间导数，必须重新检测碰撞，不能把所有改善都归因于规划算法。

## 离线运行（不启动 Gazebo、不发送运动）

先编译，再编辑 `src/panda_ompl/config/benchmark.yaml` 的七轴起终点。默认查询只是简单示例，不足以证明复杂避障能力。

```bash
RUNS=10 TIMEOUT=5.0 ./tools/compare_planners.sh
# 默认 3 算法 × 3 后处理 × 10 种子，共 90 次查询。
```

每个查询启动独立进程，避免同一 OMPL 进程反复设种子的问题。场景、机器人 URDF 和参数文件随 CSV 保存。相同种子并不意味着不同算法消耗完全相同的随机序列。不要并行运行写入同一 CSV 的进程。

输出：

- `results.csv`：每次查询的算法、种子、预算、成功、搜索时间、首解时间、整体墙钟时间、原始点数、原始/shortcut 后/输出轨迹的关节空间长度、轨迹时长、复检样本数、搜索状态检查数、回退类型及失败原因。
- `summary.csv`：每组次数、成功率、成功样本平均搜索时间/轨迹长度/时长，以及包含失败的平均整体墙钟时间。

长度为七轴角度空间中欧氏距离之和，单位记为 rad，不是米。输出轨迹长度由采样路点近似。首解时间对 RRT* 使用中间解回调；未触发回调的算法以成功 solve 返回时间近似，不能当作完全精确的首解时间。搜索状态检查数不包含全部后处理检查。整体墙钟时间包含模型加载及后处理，失败行也会记录；失败的搜索耗时未知时留空，不填写零冒充性能。

| 对比项目 | 当前证据 |
|---|---|
| 约束 B 样条抓放及提速 | 本地仿真观察到运动连续性改善，尚无量化统计 |
| 三种 C++ OMPL 的成功率、耗时、长度 | 对比工具已编写，待运行并采集数据 |
| 抓放实物接触成功率 | 尚无重复试验统计 |

建议固定环境与硬件，分别准备开放区、狭窄通道、接近障碍三个有效起终点，每组至少多种子重复，再增加时间预算曲线。这个离线工具测的是静态开爪关节查询，**不是携物完整抓放任务基准**；后者应另行记录阶段耗时、接触和实际物体最终位置。B 样条搜索后复检失败也算整个规划管线失败，不能全归因于搜索算法。
