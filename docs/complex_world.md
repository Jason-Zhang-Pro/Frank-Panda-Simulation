# 复杂任务环境：围栏取物—受限空间转运—料箱放置

启动方式和任务指令保持不变：

```bash
cd <workspace>
./start.sh
```

新终端：

```bash
source /opt/ros/humble/setup.bash
source <workspace>/install/setup.bash
ros2 service call /pick_and_place std_srvs/srv/Trigger '{}'
```

先关闭旧仿真后重新启动，才能看到新世界；链接安装下无需重新编译。

## 布局

全部单位为米、弧度，Panda 基座仍位于世界原点。

- 绿色抓取台：中心 (0.60,0.22)，台面高 0.42，尺寸 0.32×0.32，增加背部和侧部围栏。
- 红色目标方块：初始中心 (0.60,0.22,0.45)，边长 0.06，仍是可真实夹取的动态物体。
- 青色放置台：中心 (0.32,-0.55)，台面高 0.32，扩大为 0.36×0.36，并增加三面高度 0.10 的料箱围挡。
- 中央黄色隔板：中心 (0.46,-0.08)，高度 0.42，限制直接横穿。
- 蓝色顶部桥架：横梁中心高度 0.80，两个立柱形成受限空间。
- 原门架和高低圆柱继续保留；左侧圆柱移到 (0.35,0.48)，为抓取姿态保留空间。
- 后侧增加阶梯方块与斜梁，左侧增加双层货架。

总计 27 个几何部件，包括地面、两个工作台和目标物；相对上一版新增 17 个静态障碍部件。

## 规划与碰撞

仍采用现有 RRT-Connect＋shortcut，不添加人为搬运绕行点。夹取、放下的竖直动作继续使用连续逆解并逐点检查碰撞。携物时也检查红色方块与隔板、横梁、料箱等障碍物的碰撞。

world.urdf 与 world.sdf 一起更新，初始碰撞形状和位姿已逐项核对。Gazebo 中目标方块为动态模型，规划器同步其实际位姿；其余障碍物仍为静态快照，GUI 拖动物体不会自动同步。

场景更受限，随机搜索更容易耗时或失败；默认搜索预算、控制增益、夹持力上限没有因换场景而修改。失败状态请看 /planner_status。

## 文件

- src/panda_planning/worlds/world.urdf：规划场景。
- src/panda_planning/worlds/world.sdf：Gazebo 世界。
- examples/scenes/simple/world.urdf 和 world.sdf：上一版简单场景。

恢复简单场景时，把以上两个备份分别复制回 worlds/world.urdf 和 world.sdf，再重启；两份要一起恢复。


## 验证结果与限制

URDF/SDF 格式、27 个部件的碰撞几何与位姿一致性、初始姿态、抓取/抬升/放下及回程可行路径均已检查。隔离 Gazebo 测试完成了真实夹取、携物搬运、料箱内放置和松爪；完整运行中也观察到归位 RRT-Connect 在原 15 秒预算内超时，因此当前不能保证每次整套任务都归位成功。场景障碍和原规划预算没有为此降低或放宽。
