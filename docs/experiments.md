# 探索与优化记录

本记录依据开发过程与用户仿真反馈，不把未测量的观察写成定量结论。

## 从 Python 原型到 C++ 库调用

早期 Python 原型将路径搜索、轨迹生成和控制分开，帮助理解消息与任务流程。随后迁移到 C++，使用 OMPL 规划、MoveIt/FCL 碰撞、Eigen 数学运算，保持规划与力矩控制两个独立节点。规划碰撞不需要运行另一套仿真；Gazebo 负责物理世界和可视化。

当前删除 Python 算法、控制和 pybind 接口，使用资源型 ament_cmake 场景包、XML launch 和 C++ 启动协调。Git 历史保留原型演进，而主分支只呈现当前实现。

## RRT 系列与 shortcut

先探索基础 RRT，采用 RRT-Connect 改善可行路径获取；试验 RRT* 时，用户曾遇到携物搜索超时。早期 RRT* 与 C++ RRT-Connect 的比较并不公平，因为语言、实现和后处理不同。本次补齐同一 OMPL/FCL 框架下的三算法入口及重复查询脚本，尚无新定量结果。

采用无碰撞远端直连 shortcut，尽量跳过冗余中间节点，减少折线绕行。该步骤减少弯折但不自动保证速度连续，也不能把“看起来更直”称作已经找到最短路径。

## 分段停车到 B 样条

原轨迹按路点分段五次插值，每个路点速度、加速度归零，导致密集路点时可能一顿一顿。新增三次 B 样条和全段时间缩放，中间采样点保留非零导数，控制端用五次 Hermite 边界条件跟踪。改变路径后重新检测实际插值，而非只检查 RRT 路点。

最初只平滑全局运动，竖直抓放仍逐点停车。后来对抓放段也加入平滑与直线/姿态容差检查，失败回退；用户反馈抓放效果较好。

## 雅可比抓放试验与回退

试验“末端 P＋参考速度 → 阻尼雅可比伪逆 → 关节速度限幅/积分 → 关节 PD＋重力补偿”。用在线 FK 纠偏，希望避免抓放 IK 路点停车。携物预测仍用 FCL，不能因为雅可比控制就省略避障。

用户反馈下降晃动明显。曾尝试参考缓冲、速度反馈滤波、更新频率和 PD 调整，反馈未改善甚至加重；随后撤销这些抗抖修改。**没有充分测量证明振荡的唯一根因**，不能笼统断言雅可比控制不如笛卡尔规划。时序、内外环配合、阻尼、接触和积分漂移仍是待排查因素。

当前抓放已切回预规划 IK＋约束 B 样条＋关节 PD。雅可比实现保留在 `cartesian_servo.cpp`，但任务不进入在线外环。用户本地反馈本次回退效果不错，这是当前默认方案的选择依据。

## 提速与等待

在当前效果较好的方案上，关节速度比例从 0.2 提到 0.3，加速度参考上限从 0.6 提到 0.9 rad/s²；闭合最短等待从 2.2 缩至 1.4 秒，释放从 1.0 缩至 0.5 秒，仍要求接触、开口和物体位姿条件满足。用户反馈效果仍较好，尚无重复统计或严格的周期缩短比例。
